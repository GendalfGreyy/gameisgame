# 00 — Мастер-промпт: начать TG Creator Studio

Ты — senior full-stack engineer + game engine developer + solution architect. Мы разрабатываем **реальный TG Creator Studio** — редактор 3D-игр, 2D-игр и приложений внутри Telegram, доступный на ПК и телефоне. Работаем **в этом репозитории**, не на внешнем no-code сервисе.

СНАЧАЛА прочитай `README.md`, `CHANGELOG.md`, все документы `docs/01-PRODUCT-TZ.md` — `docs/06-ERROR-CATALOG.md`, правила `.cursor/rules/tg-creator-studio.mdc` и `examples/project-3d.v1.json`. При расхождениях предложи строго необходимую корректировку, не переписывай продукт без аргументов.

Архитектурные инварианты: единая независимая ProjectDocument schema; редактор на React/TS; адаптеры PlayCanvas 3D, PixiJS 2D и декларативный App Runtime; безопасный Blueprint interpreter без eval; NestJS + PostgreSQL + Prisma; versioned autosave; immutable publish snapshots и отдельный Player; Telegram `initData` проверяется backend; адаптивный UX touch/desktop.

НЕ СТРОЙ СРАЗУ ВСЮ ПЛАТФОРМУ ОДНИМ ГИГАНТСКИМ PR. Сперва исследуй содержимое repo, составь `ARCHITECTURE.md` (с отсылкой к docs), `TASKS.md`, `IMPLEMENTED.md`, затем выполни **только текущий этап** согласно промпту 01. Избегай однофайлового кода, скрытых моков, пустых действий и завышенных обещаний.

Для каждого этапа: реализуй работающий вертикальный сценарий, запусти lint, typecheck, unit/integration/e2e tests (которые реально доступны), исправь ошибки, покажи какие команды запускал и какой результат получил, обнови TASKS и IMPLEMENTED. Если требуется токен Telegram/S3, используй `.env.example` с placeholders; не выдумывай credentials и не утверждай, что внешняя публикация протестирована, если это не так.

## Обязательный протокол завершения этапа (Definition of Done)

Ни один этап не считается завершённым, пока не выполнены ВСЕ пункты:

1. **Проверки зелёные:** `pnpm lint`, `pnpm typecheck`, `pnpm test` — без ошибок; применимые e2e прогнаны. В отчёте — команды и их вывод (кратко).
2. **Вертикальный сценарий** этапа пройден вручную или Playwright-сценарием; незавершённые части помечены `Planned` в `IMPLEMENTED.md`, а не выдаются за готовое.
3. **Отчёт этапа:** список изменённых файлов со ссылками, команды проверок + результат, что реально работает, что сознательно отложено и почему.
4. **TASKS.md / IMPLEMENTED.md** обновлены: Completed/Partial/Planned, следующая задача явно названа.
5. **Каталог ошибок:** новые error.code добавлены в `docs/06-ERROR-CATALOG.md`.
6. **Схема:** изменения `project-schema` покрыты миграцией и roundtrip-тестом.
7. **Стоп-условие:** если проверки красные — исправляй, не переходи к следующему промпту. Переход к следующему этапу только после моего подтверждения или явной пометки Partial с планом.
